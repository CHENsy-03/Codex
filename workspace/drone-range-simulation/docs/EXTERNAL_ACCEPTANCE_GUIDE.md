## 三、Windows 10 实机验收——执行指南

- 验收目的：在 Windows 10 实机环境中，验证样品可按项目文档安装、启动并完成主流程；该项当前为 PENDING-EXTERNAL，不得写成 PASS（来源：TASK.md TASK-007D-R1 记录与 TASK-008 4.4）。
- 执行环境要求：实际执行的 Windows 10 版本、版本号、系统架构、机器或环境标识作为“实际执行时记录字段”，本指南不规定合格值（来源：TASK-008 4.2/4.4 证据约束：未实际运行的系统不得写成已验证）。
- 执行前准备：按项目 README 的安装与启动说明，在干净环境安装依赖并启动应用；准备一份合格地图 ZIP（来源：TASK.md TASK-007D-R1 记录“Python 3.14.4 干净环境”与 ACCEPTANCE_RECORD.md 第四节的真实数据口径）。
- 使用的产品或发布物要求：记录实际使用的发布物标识（应用版本或对应任务状态）；不得以 Windows 11 历史结果代填（来源：TASK-008 七、ACCEPTANCE_RECORD.md 二/十）。
- 操作步骤（按产品主流程顺序执行并如实记录）：
  1. 记录环境信息；
  2. 按项目文档安装依赖并启动应用；
  3. 导入合格地图 ZIP；
  4. 在地图上选择 A 点和 B 点；
  5. 输入合法飞行速度；
  6. 记录 A/B 经纬度、距离、整数秒飞行时间、HH:MM:SS 是否显示；
  7. 正常退出应用。
- 需要观察和记录的结果：启动是否成功、导入是否成功、四项结果是否显示、是否崩溃、是否存在阻断性错误、退出是否正常。
- 允许或禁止的辅助方式：按实际执行情况记录；本指南不代替实际执行。
- PASS、FAIL、BLOCKED 判定规则：
  - PASS：按上述步骤完成且全部必需结果成功显示、无崩溃、无阻断性错误；
  - FAIL：主流程无法完成或结果错误；
  - BLOCKED：环境、数据或前置条件不满足导致无法执行。
  （判定框架沿用 TASK-008 5.6 的通过条件结构；Windows 10 验收不存在额外的数值阈值。）
- 异常处理和证据保留要求：如实记录异常；实际产生的截图、日志或其他证据只有在未来确实产生后才能登记（来源：TASK-008 二、4.2）。

## 五、首次使用者两分钟验收——执行指南

以下内容完全依据 TASK.md TASK-008 第五节的冻结口径（5.1—5.8）。

- “首次使用者”资格边界：参与者此前未实际操作过该样品（5.2）。
- 验收开始前允许提供的材料：应用和依赖已安装完成、应用主窗口已打开、本地已准备一份合格地图 ZIP 并能从明确位置选择；允许参与者阅读项目提供的快速使用说明（5.1、5.2）。
- 是否允许培训、提示或协助：观察者不得进行逐步口头指导或代替参与者操作（5.2）。
- 使用者需要完成的目标（必须完成的主流程，5.4）：
  1. 导入合格地图 ZIP；
  2. 在地图上选择 A 点和 B 点；
  3. 输入合法飞行速度；
  4. 看到 A/B 经纬度；
  5. 看到距离结果；
  6. 看到整数秒飞行时间；
  7. 看到 HH:MM:SS 飞行时间。
- 计时开始条件：观察者发出开始指令，并将应用控制权交给参与者时开始计时（5.3）。
- 计时结束条件：上述结果全部成功显示时停止计时（5.5）。
- 两分钟阈值的准确判定方式：总用时不超过 120 秒，且应用没有崩溃、流程中没有无法继续的阻断性错误、所有必需结果均成功显示（5.6）；“两分钟（120 秒）”是阈值，不是实际耗时。
- 成功、失败和阻塞的判定规则：
  - PASS：总用时不超过 120 秒、无崩溃、无阻断性错误、全部必需结果成功显示；
  - FAIL：超过 120 秒、崩溃、出现阻断性错误或任一必需结果未显示；
  - BLOCKED：因环境、数据或前置条件不满足导致无法开始或完成计时。
- 中断、误操作或外部干预的记录方式：在记录表的“误操作或中断”“异常情况”栏如实记录（5.7、5.8）。
- 需要保留的证据：按 5.8 记录要求保留操作系统和环境、地图数据名称及校验信息、各步骤结果、崩溃或阻断性错误记录以及参与者和观察者确认。
- 不计入两分钟的操作：安装依赖、启动应用、准备或复制地图数据、清除点位、正常退出应用（5.7）；清除点位和正常退出可以另外验收和记录，但不得计入两分钟主流程（5.7）。
