# AI_WORKFLOW.md

> 本文档定义本仓库中人工、设计型 AI 与执行型 AI 的通用协作流程。
>
> 项目可以定义更具体的执行方式，但不得绕过“先定义任务，再最小修改，再真实验证”的基本流程。

---

## 1. 角色分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 设计者 | 需求分析、方案设计、审查、验收 | 未经授权直接修改文件或执行破坏性操作 |
| 执行者 | 按已确认方案实现、测试、检查差异 | 擅自改变方案、扩大范围、覆盖用户修改 |
| 审查者 | 检查差异、测试、风险、边界 | 在未理解上下文时直接放行 |

具体工具可以是人工、设计型 AI 或执行型 AI；角色职责优先于工具名称。

---

## 2. 单向流程

```text
用户提出需求
    ↓
需求分析
    ↓
方案设计
    ↓
开发者确认
    ↓
执行实现
    ↓
运行测试
    ↓
是否存在问题？
    ├── 否 → 审查 → 开发者确认
    └── 是 → 停止 → 输出阻塞报告
                ↓
        新的修改方案
                ↓
        继续执行
```

执行者不得在方案确认前开始大范围修改。

---

## 3. 切换条件

| 情况 | 处理 |
|---|---|
| 需求模糊 | 停止并补充需求 |
| 实现卡住 | 停止并报告阻塞 |
| 审查未通过 | 返回修复并重新审查 |
| 架构变化 | 停止并确认新方案 |
| 需要扩大范围 | 停止并请求授权 |

---

## 4. 执行异常处理

执行过程中出现以下情况必须立即停止：

- 编译或测试失败且无法确定原因；
- 架构或公共接口存在冲突；
- 任务文档与代码不一致；
- 必须修改范围外文件；
- 需要覆盖用户预存修改；
- 需要引入大型依赖；
- 无法确认业务规则。

停止后必须输出：

1. 当前执行步骤；
2. 已完成修改；
3. 修改文件列表；
4. 错误日志；
5. 当前阻塞原因；
6. 建议交给设计者或开发者分析的问题。

不得继续猜测实现。

---

## 5. 输入输出约定

| 步骤 | 输入 | 输出 |
|---|---|---|
| 需求分析 | 用户需求 | 任务定义和实施方案 |
| 方案设计 | 任务定义 | ADR（如需要） |
| 执行 | 已确认方案 | 修改后的代码和测试结果 |
| 执行异常 | 当前代码 | 错误日志、修改文件、阻塞点 |
| 审查 | Git Diff / 修改内容 | 审查意见 |
| 修复 | 审查意见 | 更新后的代码和测试 |

---

## 6. 真实报告要求

所有报告必须：

- 使用真实命令和真实输出；
- 区分已执行、未执行和无法执行；
- 不预填测试数量；
- 不虚构成功结果；
- 明确说明剩余风险；
- 不泄露秘密信息。
