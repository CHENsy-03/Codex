# ADR_PROCESS.md

> 本文档定义仓库级架构决策记录流程。
>
> 项目专属决策应记录在 `workspace/<project>/docs/decisions/`。

---

## 1. 何时使用 ADR

以下变化应考虑记录 ADR：

- 目录结构或项目边界变化；
- 跨项目共享规则变化；
- 公共接口或协议变化；
- 技术栈或基础设施变化；
- 数据存储策略变化；
- 安全边界变化；
- 影响多个项目的决策。

只影响单个项目内部模块且无需长期追溯的变化，可记录在项目变更日志中。

---

## 2. ADR 基本结构

```text
ADR-NNN：简短标题

状态：proposed / accepted / superseded / rejected
日期：YYYY-MM-DD
范围：仓库级 / 项目级
项目：workspace/<project>（项目级时填写）

## 背景
[需要做决策的原因]

## 决策
[选择方案和关键约束]

## 理由
[为什么选择该方案]

## 影响
[兼容性、维护、安全、部署等影响]

## 不采用的方案
[主要备选方案及不采用原因]
```

---

## 3. 状态流转

| 状态 | 含义 |
|---|---|
| proposed | 决策草案 |
| accepted | 已采纳 |
| superseded | 被新 ADR 替代 |
| rejected | 已拒绝 |

已接受的 ADR 不得直接改写为相反结论。

需要改变时，新增 ADR 并在旧 ADR 中注明被替代关系。

---

## 4. 记录要求

ADR 必须：

- 使用稳定编号；
- 记录真实日期和决策范围；
- 说明背景、决策、理由和影响；
- 不包含秘密信息；
- 不记录临时分支、提交 SHA 或测试数量；
- 与代码和文档保持同步。

---

## 5. 编号作用域

根级 ADR 与每个项目 ADR 分别维护独立编号序列。

- ADR 编号只要求在所属作用域的 `docs/decisions/` 目录内唯一。
- 不同项目之间、项目与根级之间允许出现相同编号，例如都可以存在 `ADR-001.md`。
- 根级仓库级 ADR 存放于：
  ```text
  docs/decisions/ADR-NNN.md
  ```
- 项目级 ADR 存放于：
  ```text
  workspace/<project>/docs/decisions/ADR-NNN.md
  ```
- 项目级 ADR 必须在正文中明确项目名称或项目路径。
- 引用 ADR 时，应同时给出作用域或真实相对路径，不能只写裸编号并假设全仓库唯一。
- 新 ADR 的编号根据所属目录中现有 ADR 的最大编号递增，不得依据其他作用域的编号决定。
- 如果某个作用域还没有带编号的 ADR，则从 `ADR-001` 开始。
- `ADR_PROCESS.md` 是流程说明文件，不属于任何编号序列，无需改名为带编号 ADR。
- 已发布 ADR 的编号应保持稳定，不得为了全仓库连续或避免跨作用域重号而随意重编号。
- ADR 迁移到正确项目作用域时，原则上保留历史编号，并通过适用范围和变更记录说明归属。

例如，根级未来第一份正式仓库级 ADR 可以使用 `ADR-001`；它与 `workspace/crawler/docs/decisions/ADR-001.md` 不冲突，因为两者属于不同作用域。
